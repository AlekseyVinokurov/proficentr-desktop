# Proficentr Desktop

Windows-приложение для учебных центров дополнительного профессионального образования (ДПО) и профессионального обучения (ПО). Помогает вести сведения об учебном центре и совершеннолетних слушателях в локальном хранилище.

Программа развивается как публичный проект и рассчитана на использование в разных образовательных организациях. Текущая версия — **0.2.0**, первый стабильный релиз ещё не опубликован.

## Возможности

- Локальная работа без сервера, интерфейс на PySide6.
- Выбор каталога для базы SQLite и подготовленная структура электронного архива.
- Карточка учебного центра: реквизиты, руководитель, лицензия и логотип.
- Реестр совершеннолетних слушателей: поиск, создание и редактирование карточек.
- Реестр организаций-заказчиков: юридические лица и ИП, реквизиты и контакты, поиск по наименованию, ИНН и телефону, предупреждения о возможных дублях.
- Проверка формата введённых данных, контрольной суммы СНИЛС и предупреждение о возможных дублях. Проверки не подтверждают принадлежность документов человеку.
- Справочник образовательных программ ДПО и ПО: структурированные виды, продолжительность в академических часах, реквизиты редакции, поиск, фильтры и архивирование без удаления.
- Учебные группы и индивидуальные обучения: выбор существующих слушателей и программ, плановые даты, проверка возраста на начало обучения, снимок программы, состав и архив групп.
- DOCX-шаблоны: загрузка и проверка собственных форм, история версий, выбор активной версии, выгрузка копии в Word и тестовая генерация на вымышленных данных. [Инструкция](docs/templates.md).
- Договоры на одно или несколько обучений по одной программе: заказчик-слушатель, другое физлицо, организация или ИП; черновики, проект DOCX, регистрация с номером, архив и аннулирование с сохранением оригинала.
- Приказы о зачислении: индивидуальный или выбранная часть группы, проект DOCX, регистрация с номером и отдельное ручное подтверждение подписания; защита зачисленных обучений от изменений.
- Локальный пакет из копии приказа и связанных зарегистрированных договоров с проверкой целостности.
- Подготовленный механизм обновления из официальных GitHub Releases с проверкой подписи пакета.

Выпуск, обмен с ФИС ФРДО и импорт исторического архива пока не реализованы. Это направления дальнейшего развития без объявленных сроков. Для договоров и приказов используются ваши утверждённые формы; их соответствие применимым требованиям и локальным актам нужно проверить до эксплуатации. Роли сотрудников, аудит изменений и шифрование пользовательской базы также пока отсутствуют.

## Установка

Официальные стабильные версии должны распространяться через [GitHub Releases этого репозитория](https://github.com/AlekseyVinokurov/proficentr-desktop/releases). Проверочные сборки предназначены для 64-разрядной Windows. Пока стабильных релизов нет, для ознакомления доступны **проверочные сборки GitHub Actions**. Они не являются стабильными релизами и не используются встроенным механизмом обновления.

1. Откройте [Actions → Windows — тесты и сборка](https://github.com/AlekseyVinokurov/proficentr-desktop/actions/workflows/windows.yml).
2. Выберите успешный запуск для ветки `main`. В разделе **Artifacts** скачайте `Proficentr-Desktop-Windows`.
3. Распакуйте скачанный архив артефакта, затем находящийся внутри `Proficentr-0.2.0-Windows.zip`.
4. Сохраните всю папку `Proficentr` в доступном вам локальном каталоге, например `%LOCALAPPDATA%\Programs`, и запустите `Proficentr.exe` внутри неё.

Оставьте рядом с EXE папку `_internal` и файл `ProficentrUpdater.exe`; переносить один EXE отдельно нельзя. Python на компьютере пользователя не нужен. Проверочная сборка хранится 14 дней: если артефакт истёк, выберите более свежий успешный запуск. Для скачивания артефактов нужен вход в GitHub ([инструкция GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)); сама программа регистрации и GitHub-токена не требует.

## Начало работы

1. При первом запуске выберите пустую папку на локальном диске для рабочих данных, например `D:\ProficentrData`. Храните её отдельно от папки программы, вне сетевых дисков и папок облачной синхронизации.
2. Откройте **Настройки → Учебный центр**, заполните реквизиты и при необходимости добавьте логотип. Примените изменения кнопкой **Сохранить**.
3. В разделе **Слушатели** создайте карточку. Обязательны фамилия, имя и дата рождения; слушателю должно быть не менее 18 лет на текущую дату компьютера. Остальные сведения можно добавить позже.
4. В разделе **Организации** добавьте контрагента: выберите юридическое лицо или ИП и укажите полное наименование. Остальные реквизиты можно заполнить позже; КПП для ИП не требуется. Это отдельный реестр заказчиков, не карточка вашего учебного центра.
5. В разделе **Программы** укажите наименование, направление ДПО или ПО, соответствующий вид и положительное число академических часов. Неактуальную программу можно отправить в архив и позднее вернуть; архивные записи доступны через фильтр статуса.
6. В разделе **Группы** создайте учебную группу и откройте **Состав группы**, чтобы найти и добавить существующих слушателей. Для выбора нескольких строк используйте Ctrl или Shift. На вкладке **Индивидуальное обучение** можно подготовить обучение без группы. Состояние **Подготовка** ещё не означает зачисления.
7. В **Настройки → Шаблоны документов** загрузите свой DOCX с разрешёнными полями и сформируйте тестовый документ. Для правок откройте копию в Word, затем загрузите новую версию. Тестирование формы использует только вымышленные сведения. Для договоров настройте тип заказчика и вариант `dpo`/`po` или `dpo-…`/`po-…`.
8. В разделе **Документы → Договоры** выберите обучения и заказчика, укажите дату, общую стоимость и условия оплаты. Сформируйте и проверьте проект, затем подтвердите регистрацию. Номер присваивается при регистрации, окончательный DOCX сохраняется в архиве. Для исторического договора введите исходный номер и дату. Регистрация не означает подписание сторонами и не зачисляет слушателя.
9. В **Документы → Приказы о зачислении** создайте черновик, выберите существующие обучения и активную форму, сформируйте и проверьте проект, затем зарегистрируйте приказ. Номер присваивается только при регистрации (например, `З-2026-0001`); можно указать исторические номер и дату.
10. После фактического подписания выберите приказ и **Подтвердить подписание**: укажите дату подписания, ответственного и вручную подтвердите проверку оснований/договоров и применимых условий образования. Только тогда выбранные обучения станут **Зачислен** и будут защищены от обычного изменения. Программа не проверяет подлинность подписи или юридическую достаточность оснований.
11. **Подготовить пакет документов** сохраняет в `exports/enrollment-packages/` проверенные копии приказа и связанных зарегистрированных договоров. Пакет локальный, не универсальный обязательный комплект; согласия автоматически не создаются. Подписание договоров отдельно не учитывается.
12. Используйте поиск для открытия и редактирования карточек. При предупреждении о дубле проверьте найденную запись перед созданием отдельной карточки.

Выбранное хранилище сохраняется в настройках. Для резервного копирования закройте программу и скопируйте весь каталог данных. Перенос в другую папку доступен в **Настройки → Хранилище**; подробные условия — в [техническом руководстве](docs/development.md#данные).

## Обновления

В **Настройки → О программе** показаны установленная версия, официальный источник и состояние обновлений. Проверка выполняется при запуске не чаще раза в сутки или вручную кнопкой **Проверить обновления**. При наличии новой версии отображается описание изменений.

Установка необязательна. После подтверждения кнопкой **Обновить и перезапустить** программа проверяет подпись пакета Ed25519 встроенным публичным ключом, размер и SHA-256 архива. Пакет без корректной подписи не устанавливается. Новая версия готовится отдельно, внешний процесс переключает программные файлы после закрытия приложения и проверяет запуск. Прежние файлы сохраняются; выбранное хранилище и настройки остаются на месте.

Сборки 0.1.0 требуют ручного перехода на версию с механизмом обновления. Пока стабильные релизы не опубликованы, проверить переход между двумя опубликованными официальными версиями невозможно. Порядок установки, ограничения и восстановление при сбое описаны в [документации обновлений](docs/updates.md).

## Конфиденциальность и хранение данных

Рабочие данные хранятся **локально, в выбранном пользователем хранилище**. Приложение не отправляет разработчику или сторонним сервисам содержимое базы, персональные данные, сведения об организациях, документы, фотографии и сканы. Скрытая телеметрия, аналитика, удалённый сбор данных и удалённый доступ разработчика к базе не используются.

Для проверки и загрузки обновлений программа обращается к официальной инфраструктуре GitHub, не передавая пользовательские сведения и файлы. GitHub может получать IP-адрес и стандартные технические сведения о подключении. Без интернета основные функции программы доступны.

Организация, эксплуатирующая программу, отвечает за организацию доступа к рабочим данным, резервное копирование и необходимые меры защиты в пределах своих законных обязанностей.

**SQLite по умолчанию не шифрует данные. Роли сотрудников, аудит и криптографическая защита пользовательской базы ещё не реализованы.** До эксплуатации с реальными персональными данными необходимо обеспечить и проверить соответствующие организационные и технические меры защиты. Одного пароля Windows недостаточно для комплексной защиты. Абсолютная безопасность и полное соответствие всем требованиям законодательства без отдельной проверки не гарантируются. Подробнее — в [SECURITY.md](SECURITY.md).

## Форки и сторонние сборки

Исходный код опубликован в GitHub. Сторонние разработчики технически могут создавать копии репозитория и изменённые сборки; форк не даёт автоматического права изменять официальный репозиторий. Условия использования, изменения и распространения исходного кода будут определяться выбранной лицензией.

Официальное приложение получает обновления только из официального репозитория и не доверяет сторонним источникам. Публичность исходников сама по себе не подтверждает безопасность стороннего EXE. Изменения в независимой сторонней сборке не следует автоматически приписывать разработчику официальной версии; происхождение такой сборки нужно проверять отдельно.

## Индивидуальные доработки

Программу можно адаптировать под процессы конкретного учебного центра. Возможные направления индивидуальных работ: дополнительные формы документов, автоматизация специализированных процессов, интеграции с существующими системами, разграничение прав доступа, расширенное журналирование, усиленная защита персональных данных и шифрование.

Объём, стоимость и техническое решение определяются отдельно. Перечисленные доработки не являются уже встроенными возможностями текущей версии. Обсудить задачу можно через GitHub Issues без публикации рабочих данных.
