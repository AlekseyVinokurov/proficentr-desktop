# Proficentr Desktop

Настольное Windows-приложение для автоматизации документооборота учебных центров ДПО и ПО. Первый пользователь — ЧУ ДПО «Профицентр-2»; каркас не привязан к одной организации.

Состояние **P02.2**: окно PySide6 с восемью разделами, настраиваемое локальное хранилище, SQLite с миграциями, реестр слушателей, карточка учебного центра с логотипом, основа электронного архива и Windows-сборка. Организации-заказчики, обучение, группы, договоры, генераторы документов и обмен с ФИС ФРДО пока не реализованы.

## Запуск из исходного кода

Нужен Python 3.12. В Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m proficentr
```

В Linux / WSL:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m proficentr
```

Для обычного окна Linux нужен графический дисплей (в WSL — WSLg). Проверка без дисплея:

```bash
QT_QPA_PLATFORM=offscreen PROFICENTR_DATA_DIR=/tmp/proficentr-smoke .venv/bin/python -m proficentr --smoke-test
.venv/bin/python -m pytest -q
```

`--smoke-test` открывает окно, проверяет все переходы и автоматически завершает приложение. Тесты используют временные базы и синтетические данные.

## Данные

При первом запуске выберите пустую локальную папку, например `D:\ProficentrData` (кириллица и пробелы допустимы). Отмена выбора завершает запуск без создания базы. Каталог не связан с расположением EXE. В нём автоматически создаются:

```text
database/proficentr.sqlite3
documents/
attachments/
templates/
organization/
exports/
```

Путь сохраняется атомарно в отдельном пользовательском файле настроек: Windows — `%LOCALAPPDATA%\Proficentr\settings.json`; Linux — `$XDG_CONFIG_HOME/proficentr/settings.json`, по умолчанию `~/.config/proficentr/settings.json`. Обновление или переустановка приложения не меняет выбранный путь. Не удаляйте этот файл при обновлении. Если настроенный диск или база недоступны, приложение сообщает об ошибке и не создаёт пустую замену.

Старая база P01 (`%LOCALAPPDATA%\Proficentr\proficentr.sqlite3` либо `$XDG_DATA_HOME/proficentr/proficentr.sqlite3`, по умолчанию `~/.local/share/proficentr/proficentr.sqlite3`) обнаруживается автоматически: SQLite Backup API создаёт проверенную копию в `database/`, а исходный файл сохраняется. При конфликте двух баз автоматический выбор отменяется.

На странице **Настройки** показаны каталог, путь к SQLite и состояние доступности. Кнопка выбора папки предлагает перенести базу и содержимое пяти каталогов архива. Назначение должно быть пустым и находиться вне исходного хранилища. Перед переносом закройте другие экземпляры приложения. Проверяются запись, свободное место (с запасом 16 МиБ) и конфликты; база копируется через SQLite Backup API с учётом WAL и проверяется `integrity_check`. Новый путь сохраняется только после успешного копирования. При ошибке прежняя конфигурация и исходные данные сохраняются. После успеха приложение закрывается: запустите его снова. Старую копию автоматически не удаляем; перед её ручным удалением убедитесь, что новый архив работает.

Для явного задания пути, в том числе в CI, сохранена `PROFICENTR_DATA_DIR` — абсолютный локальный каталог (PowerShell: `$env:PROFICENTR_DATA_DIR = 'D:\ProficentrData'`). Переменная имеет приоритет; при первом использовании хранилище инициализируется, путь сохраняется в настройках. При активной переменной перенос через интерфейс отключён: уберите её и перезапустите приложение. Для тестового запуска задавайте отдельный каталог данных и конфигурации.

Храните данные вне исходников и папки EXE. Приложение отклоняет UNC, подключённые сетевые диски Windows, известные сетевые файловые системы Linux и явно распознанные папки OneDrive, Dropbox и Google Drive (по имени либо известной переменной окружения). Все клиенты синхронизации автоматически определить невозможно: пользователь должен выбирать обычную локальную папку. Совместная работа через сетевой SQLite не поддерживается. Для резервного копирования закройте приложение и скопируйте каталог данных. Символические ссылки в каталогах архива при переносе отклоняются.

Схема содержит `schema_migrations`, добавленную миграцией № 2 таблицу `training_center` и добавленную миграцией № 3 таблицу `students`. Миграции в `database.py` применяются последовательно в транзакции; новые добавляются в конец списка. Более новая схема отклоняется, соединение закрывается при выходе и при ошибке запуска.

## Реестр слушателей

В разделе **Слушатели** можно добавить человека, найти, открыть и исправить его карточку. Таблица содержит ФИО, дату рождения, телефон и email. Поиск учитывает частичные совпадения, работает с русскими буквами без учёта регистра, а для телефона и СНИЛС допускает ввод с пробелами и разделителями. После сохранения список обновляется, прежний фильтр сбрасывается и сохранённая строка выделяется.

Для создания обязательны фамилия, имя и дата рождения; возраст на текущую дату компьютера должен составлять 18 лет или больше. Пограничный возраст проверяется по месяцу и дню рождения (для 29 февраля в невисокосном году — с 1 марта). При будущем зачислении потребуется самостоятельная проверка возраста на дату начала обучения. Даты вводятся и хранятся как `ГГГГ-ММ-ДД`. Избыточные пробелы убираются, регистр имён сохраняется. Отчество, гражданство, контакты, паспорт, образование, работа и примечание могут быть заполнены позже. Паспортная серия проверяется как 4 цифры, номер — 6, код подразделения — `000-000`; дата выдачи не может предшествовать рождению или находиться в будущем.

СНИЛС необязателен; если введён, проверяются формат и контрольная сумма. В базе сохраняются 11 цифр без разделителей. Для старых номеров до `001-001-998` включительно применяется проверка формата без контрольной суммы; нулевой номер отклоняется. Алгоритм описан в [правилах расчёта контрольной суммы ТФОМС](https://rostov-tfoms.ru/services/zasedaniya-rabochih-grupp/erp/pravila-rascheta-kontrolnoj-summy-snils). Проверка не подтверждает принадлежность номера человеку и не обращается к внешним сервисам.

Перед сохранением проверяются точное совпадение заполненного СНИЛС и возможное совпадение ФИО с датой рождения. Предупреждение различает эти причины, позволяет открыть выбранную существующую карточку либо явно сохранить отдельную запись. Открытие найденной карточки отменяет текущие несохранённые изменения. Однофамильцы допустимы; автоматического объединения и уникальности ФИО нет. Сохранение карточки выполняется транзакционно. При отмене и закрытии изменённой формы можно сохранить изменения, отказаться от них или продолжить редактирование.

Постоянный идентификатор — внутренний `students.id`, который не меняется при исправлении ФИО, паспорта или СНИЛС. Повторное обучение в будущем должно ссылаться на существующего слушателя. Связи «слушатель → несколько обучений», «обучение → программа, группа, договоры и документы» пока не создаются. Физическое удаление через интерфейс отсутствует. Изменение карточки не должно менять исторические документы: в следующих этапах они будут хранить снимок данных, а исправления зарегистрированных сведений — пользователя, дату, старое и новое значение в журнале аудита. Сейчас снимки, аудит, роли и архивный статус не реализованы.

**До работы с реальными персональными данными необходимо отдельно реализовать и проверить защиту доступа и хранения.** SQLite не защищает от копирования. Рабочие базы, паспортные данные и СНИЛС не должны попадать в GitHub. Модуль слушателей не пишет данные в логи; диагностические сообщения SQLite заменяются нейтральными сообщениями. Все данные автоматических тестов вымышлены.

## Карточка учебного центра

Откройте **Настройки → Учебный центр**. Это реквизиты вашей образовательной организации, отдельно от будущих организаций-заказчиков. Доступны общие сведения, адреса и контакты, банковские реквизиты, сведения о руководителе и лицензии. Поля необязательны: карточку можно заполнять постепенно. Для введённых ИНН, КПП, ОГРН / ОГРНИП, email, БИК и счетов проверяется формат, без проверки контрольных сумм или обращения к внешним реестрам. Дата лицензии вводится как `ГГГГ-ММ-ДД`.

Изменения реквизитов, загрузка, замена и удаление логотипа применяются только кнопкой **Сохранить**. При уходе из формы, смене раздела или закрытии окна можно сохранить изменения, отказаться от них или отменить выход. Повторное открытие приложения восстанавливает сохранённые данные. В каждой базе допустима только одна карточка (`id = 1`); повторное сохранение обновляет её.

Логотип PNG / JPG ограничен 5 МиБ и 25 млн пикселей; проверяется содержимое изображения. Предпросмотр работает до сохранения. Файл сохраняется в `organization/`, в SQLite хранится относительный путь. Перенос хранилища P01.1 сохраняет доступность логотипа. Новый файл записывается до транзакции SQLite: при ошибке записи реквизитов он удаляется, прежний логотип сохраняется. После успешной замены или удаления привязки прежний файл удаляется; если очистка недоступна, интерфейс сообщает об оставшемся файле. Прерывание питания между записью файла и транзакцией может оставить неиспользуемый файл, не заменяя действующий логотип.

Для будущих документов реквизиты должны браться через `TrainingCenterRepository`. При регистрации документа потребуется сохранять снимок использованных реквизитов: последующие изменения карточки не должны менять зарегистрированные, исторические или подписанные документы. Исторические договоры и приказы могут использовать прежние реквизиты. Изменения карточки в будущем должны учитываться журналом аудита. В P02.1 снимки документов, версионирование, реестры, генерация и аудит не реализуются.

## Структура

```text
src/proficentr/
  __main__.py       точка входа и жизненный цикл
  settings.py       пользовательские пути
  storage.py        структура архива, пути документов, безопасный перенос
  database.py       SQLite и миграции
  organization.py   карточка учебного центра, валидация и файлы логотипа
  students.py       модель слушателя и валидация
  student_repository.py поиск, проверка дублей и операции SQLite
  services.py       сценарий запуска, место бизнес-логики
  ui/main_window.py окно, навигация и страницы
  ui/settings_page.py выбор и перенос хранилища
  ui/training_center_page.py форма реквизитов и предпросмотр логотипа
  ui/students_page.py реестр и поиск слушателей
  ui/student_dialog.py карточка слушателя и проверка дублей
run_proficentr.py   точка входа PyInstaller
tests/             тесты БД, настроек, импорта и интерфейса
.github/workflows/windows.yml
```

Документы и ФРДО пока представлены отдельными страницами. Их реализация на следующих этапах будет вынесена в модули `documents` и `frdo`; пустые пакеты заранее не создаются.

## Основа электронного архива

Единый сервис `Storage.document_directory(document_date, category)` создаёт по запросу путь `documents/YYYY/MM/<category>/`. Принимаются категории `contracts`, `orders`, `protocols`, `issued`, `other`. Год и месяц берутся из даты документа, включая исторические даты; пустые годы и категории заранее не создаются. Интерфейс и будущие генераторы должны получать пути только через этот сервис, а в базе хранить пути относительно корня хранилища.

Правила следующих этапов, которые пока не реализуются:

- Новые договоры, приказы, протоколы и выпускные документы формируются и сохраняются автоматически.
- Номер документа хранится и управляется реестром SQLite, а не именем файла.
- Дата документа и фактическая дата внесения учитываются раздельно. Исторические документы могут сохранять первоначальные номера.
- Существующие документы импортируются через контролируемый интерфейс с указанием категории; непосредственное копирование в архив не заменяет регистрацию.
- Изменения зарегистрированных документов фиксируются в журнале; подписанные оригиналы не перезаписываются.
- Изменения карточек слушателей не изменяют исторические документы автоматически.
- Для бумажных оригиналов предусматривается учёт местонахождения.

P01.1 подготовил основу хранения; P02.1 добавил карточку учебного центра, P02.2 — реестр слушателей. Реестры документов, нумерация, генерация DOCX, исторический импорт, права доступа и журнал исправлений остаются для следующих этапов. Ранее применённые миграции сохранены без изменений.

## Windows-сборка

Тяжёлая сборка выполняется только в GitHub Actions: при `push` или вручную через **Actions → Windows — тесты и сборка → Run workflow**. Workflow устанавливает Python 3.12 и зависимости `.[test,build]`, запускает pytest, собирает приложение PyInstaller в режиме `onedir`, проверяет запуск EXE дважды и создание SQLite, затем загружает артефакт `Proficentr-Desktop-Windows`.

Скачайте артефакт со страницы успешного запуска Actions. Внутри находится `Proficentr-Desktop-Windows.zip`; распакуйте его целиком и запустите `Proficentr/Proficentr.exe`. Папка `_internal` должна оставаться рядом с EXE. Python на компьютере пользователя не нужен. Срок хранения артефакта — 14 дней. Автоматическая публикация GitHub Releases не настроена.

Команда сборки в CI соответствует [документации PyInstaller](https://pyinstaller.org/en/stable/usage.html):

```text
python -m PyInstaller --noconfirm --clean --onedir --windowed --name Proficentr --paths src run_proficentr.py
```

Лицензия проекта на этапе P01 не выбрана. Не добавляйте в Git персональные данные, сканы, рабочие базы и секреты; соответствующие файлы и каталоги включены в `.gitignore`.
