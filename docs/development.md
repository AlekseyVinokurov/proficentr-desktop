# Техническое руководство

Здесь собраны инструкции разработчика, устройство локального хранилища и ограничения реализованных модулей. Пользовательское описание и установка — в [README](../README.md). Этапы и результаты проверок — в [состоянии проекта](project-status.md); протокол обновлений, выпуск и восстановление — в [updates.md](updates.md); правила безопасности — в [SECURITY.md](../SECURITY.md).

Приложение предназначено для Windows; основная среда разработки — Python 3.12, VS Code, WSL Ubuntu и Git. Первый пользователь — ЧУ ДПО «Профицентр-2», но архитектура не привязана к одной организации.

## Запуск из исходного кода

Нужен Python 3.12. В Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m proficentr
```

В Linux / WSL:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m proficentr
```

Для обычного окна Linux нужен графический дисплей (в WSL — WSLg). Проверка без дисплея:

```bash
QT_QPA_PLATFORM=offscreen XDG_CONFIG_HOME=/tmp/proficentr-smoke-config PROFICENTR_DATA_DIR=/tmp/proficentr-smoke .venv/bin/python -m proficentr --smoke-test
.venv/bin/python -m pytest -q
```

`--smoke-test` открывает окно, проверяет все переходы и автоматически завершает приложение. Тесты используют временные базы и синтетические данные.

Для воспроизведения фиксированного окружения CI вместо установки `.[test]` установите `requirements-release.txt`, затем проект без повторного разрешения зависимостей:

```text
python -m pip install -r requirements-release.txt
python -m pip install --no-deps -e .
python -m pip check
```

Лёгкие проверки безопасности в этом окружении:

```text
python scripts/security_check.py
python -m bandit -r src -q
python -m pip_audit -r requirements-release.txt --disable-pip --no-deps
```

CI дополнительно проверяет историю Git через Gitleaks; исключён только конкретный отпечаток публичного ключа. Обновляйте фиксированные зависимости осознанно, с проверкой известных уязвимостей. Эти инструменты не доказывают отсутствие всех уязвимостей.


## Данные

При первом запуске выберите пустую локальную папку, например `D:\ProficentrData` (кириллица и пробелы допустимы). Отмена выбора завершает запуск без создания базы. Каталог не связан с расположением EXE. В нём автоматически создаются:

```text
database/proficentr.sqlite3
documents/
attachments/
templates/
organization/
exports/
```

Путь сохраняется атомарно в отдельном пользовательском файле настроек: Windows — `%LOCALAPPDATA%\Proficentr\settings.json`; Linux — `$XDG_CONFIG_HOME/proficentr/settings.json`, по умолчанию `~/.config/proficentr/settings.json`. Обновление или переустановка приложения не меняет выбранный путь. Не удаляйте этот файл при обновлении. Если настроенный диск или база недоступны, приложение сообщает об ошибке и не создаёт пустую замену.

Старая база P01 (`%LOCALAPPDATA%\Proficentr\proficentr.sqlite3` либо `$XDG_DATA_HOME/proficentr/proficentr.sqlite3`, по умолчанию `~/.local/share/proficentr/proficentr.sqlite3`) обнаруживается автоматически: SQLite Backup API создаёт проверенную копию в `database/`, а исходный файл сохраняется. При конфликте двух баз автоматический выбор отменяется.

На странице **Настройки** показаны каталог, путь к SQLite и состояние доступности. Кнопка выбора папки предлагает перенести базу и содержимое пяти каталогов архива. Назначение должно быть пустым и находиться вне исходного хранилища. Перед переносом закройте другие экземпляры приложения. Проверяются запись, свободное место (с запасом 16 МиБ) и конфликты; база копируется через SQLite Backup API с учётом WAL и проверяется `integrity_check`. Новый путь сохраняется только после успешного копирования. При ошибке прежняя конфигурация и исходные данные сохраняются. После успеха приложение закрывается: запустите его снова. Старую копию автоматически не удаляем; перед её ручным удалением убедитесь, что новый архив работает.

Для явного задания пути, в том числе в CI, сохранена `PROFICENTR_DATA_DIR` — абсолютный локальный каталог (PowerShell: `$env:PROFICENTR_DATA_DIR = 'D:\ProficentrData'`). Переменная имеет приоритет; при первом использовании хранилище инициализируется, путь сохраняется в настройках. При активной переменной перенос через интерфейс отключён: уберите её и перезапустите приложение. Для тестового запуска задавайте отдельный каталог данных и конфигурации.

Храните данные вне исходников и папки EXE. Приложение отклоняет UNC, подключённые сетевые диски Windows, известные сетевые файловые системы Linux и явно распознанные папки OneDrive, Dropbox и Google Drive (по имени либо известной переменной окружения). Все клиенты синхронизации автоматически определить невозможно: пользователь должен выбирать обычную локальную папку. Совместная работа через сетевой SQLite не поддерживается. Для резервного копирования закройте приложение и скопируйте каталог данных. Символические ссылки в каталогах архива при переносе отклоняются.

Схема содержит `schema_migrations`, добавленную миграцией № 2 таблицу `training_center`, добавленную миграцией № 3 таблицу `students`, добавленную миграцией № 4 таблицу `counterparties`, добавленную миграцией № 5 таблицу `programs` добавленные миграцией № 6 таблицы `training_groups` и `trainings` и реестр `document_templates` миграции № 7. Миграции в `database.py` применяются последовательно в транзакции; новые добавляются в конец списка. Более новая схема отклоняется, соединение закрывается при выходе и при ошибке запуска. Порядок резервирования, пробных миграций и восстановления описан в [updates.md](updates.md#sqlite-и-восстановление).

## Реестр слушателей

В разделе **Слушатели** можно добавить человека, найти, открыть и исправить его карточку. Таблица содержит ФИО, дату рождения, телефон и email. Поиск учитывает частичные совпадения, работает с русскими буквами без учёта регистра, а для телефона и СНИЛС допускает ввод с пробелами и разделителями. После сохранения список обновляется, прежний фильтр сбрасывается и сохранённая строка выделяется.

Для создания обязательны фамилия, имя и дата рождения; возраст на текущую дату компьютера должен составлять 18 лет или больше. Пограничный возраст проверяется по месяцу и дню рождения (для 29 февраля в невисокосном году — с 1 марта). При будущем зачислении потребуется самостоятельная проверка возраста на дату начала обучения. Даты вводятся и хранятся как `ГГГГ-ММ-ДД`. Избыточные пробелы убираются, регистр имён сохраняется. Отчество, гражданство, контакты, паспорт, образование, работа и примечание могут быть заполнены позже. Паспортная серия проверяется как 4 цифры, номер — 6, код подразделения — `000-000`; дата выдачи не может предшествовать рождению или находиться в будущем.

СНИЛС необязателен; если введён, проверяются формат и контрольная сумма. В базе сохраняются 11 цифр без разделителей. Для старых номеров до `001-001-998` включительно применяется проверка формата без контрольной суммы; нулевой номер отклоняется. Алгоритм описан в [правилах расчёта контрольной суммы ТФОМС](https://rostov-tfoms.ru/services/zasedaniya-rabochih-grupp/erp/pravila-rascheta-kontrolnoj-summy-snils). Проверка не подтверждает принадлежность номера человеку и не обращается к внешним сервисам.

Перед сохранением проверяются точное совпадение заполненного СНИЛС и возможное совпадение ФИО с датой рождения. Предупреждение различает эти причины, позволяет открыть выбранную существующую карточку либо явно сохранить отдельную запись. Открытие найденной карточки отменяет текущие несохранённые изменения. Однофамильцы допустимы; автоматического объединения и уникальности ФИО нет. Сохранение карточки выполняется транзакционно. При отмене и закрытии изменённой формы можно сохранить изменения, отказаться от них или продолжить редактирование.

Постоянный идентификатор — внутренний `students.id`, который не меняется при исправлении ФИО, паспорта или СНИЛС. Повторные обучения ссылаются на существующего слушателя через `trainings.student_id`; программа и необязательная группа имеют собственные внешние ключи. Договоры и документы пока не привязываются. Физическое удаление через интерфейс отсутствует. Изменение карточки не должно менять исторические документы: в следующих этапах они будут хранить снимок данных, а исправления зарегистрированных сведений — пользователя, дату, старое и новое значение в журнале аудита. Сейчас снимки реквизитов слушателя, аудит, роли и архивный статус карточки слушателя не реализованы.

Требования к защите и сообщениям об уязвимостях — в [SECURITY.md](../SECURITY.md). Модуль слушателей не пишет данные в логи; диагностические сообщения SQLite заменяются нейтральными сообщениями. Все данные автоматических тестов вымышлены.

## Организации-заказчики

Реестр `counterparties` и `CounterpartyRepository` отделены от `training_center` и `TrainingCenterRepository`. Типы — `legal_entity` (юридическое лицо) и `sole_proprietor` (ИП); физические лица как заказчики здесь не учитываются. Постоянный внутренний ID сохраняется при исправлении реквизитов. Для создания достаточно типа и полного наименования; сокращённое наименование, контакты, адреса, банковские реквизиты, представитель, основание полномочий, реквизиты доверенности и примечание необязательны. Форма прокручивается; сохранение выполняется транзакционно, закрытие изменённой карточки предлагает сохранить, отказаться от правок или продолжить редактирование. Физического удаления через интерфейс нет.

Для заполненных реквизитов проверяется формат: ИНН — 10 цифр у юридического лица и 12 у ИП; ОГРН — 13, ОГРНИП — 15; КПП — 9 знаков с допустимыми латинскими буквами в позициях 5–6; БИК — 9 цифр; банковские счета — 20 цифр; email — локальная проверка формата. Контрольные суммы налоговых и банковских реквизитов не проверяются, обращения к внешним реестрам отсутствуют. Для ИП КПП не применяется; при смене типа заполненный КПП очищается только с подтверждением и только в форме до сохранения.

Поиск учитывает полное и сокращённое наименования без учёта регистра русских букв, ИНН и телефон; для числового запроса допускаются пробелы и разделители. Возможные дубли определяются по точному заполненному ИНН либо полному/сокращённому наименованию без учёта регистра и избыточных пробелов. Текущая карточка исключается. Предупреждение позволяет открыть найденную карточку, отменить сохранение или явно сохранить отдельную запись; автоматического объединения и уникальности ИНН нет. Открытие найденной карточки отменяет текущие несохранённые правки. После сохранения фильтр очищается и запись выделяется. Ошибки репозитория не раскрывают содержимое карточек и исходные сообщения SQLite; данные не записываются в логи.

Одна организация в дальнейшем сможет быть заказчиком нескольких договоров и обучения нескольких слушателей независимо от их места работы. Связи с обучением, договорами и оплатой сейчас не создаются. При регистрации договоров потребуются снимки реквизитов: изменения карточки не должны менять исторические документы. Эта задача и договоры с физическими лицами относятся к P03.

## Образовательные программы

Таблица `programs`, модель `Program` и `ProgramRepository` образуют отдельный справочник. Направление (`dpo` / `po`) и вид хранятся структурированно. В ДПО предусмотрены повышение квалификации и профессиональная переподготовка; в ПО — профессиональная подготовка по профессиям рабочих и должностям служащих, переподготовка и повышение квалификации рабочих и служащих. Совместимость направления и вида проверяется в модели и ограничением SQLite; смена направления в форме сбрасывает прежний вид и требует выбрать подходящий.

Обязательны полное наименование, направление, вид и положительное целое число академических часов. Произвольный предельный срок обучения не задан; хранение целого ограничено числовым форматом SQLite. Необязательны сокращённое наименование, внутренний код, квалификация/профессия/должность, разряд/категория, дата/номер/другие сведения об утверждении, редакция и примечание. Квалификация и разряд заполняются только при применимости, одинаковых требований ко всем видам нет. Дата проверяется как существующая дата `ГГГГ-ММ-ДД`; нормативные ограничения объёма, зачисления и аттестации не реализованы. Стоимость и даты конкретного обучения к справочнику не привязаны.

По умолчанию видны активные программы; фильтры позволяют выбрать направление и активные/архивные/все записи. Поиск работает по полному и сокращённому наименованию и внутреннему коду без учёта регистра русских букв и избыточных пробелов. Совпадение полного наименования или заполненного кода вызывает предупреждение, включая архивные программы; текущая карточка исключается. В предупреждении видны вид, часы, редакция и статус. Можно открыть найденную карточку, отменить сохранение или явно сохранить отдельную программу, в том числе с одинаковым названием и другой редакцией. Автоматического объединения и уникальности названия/кода нет.

«В архив» и «Вернуть в активные» изменяют только статус с подтверждением, сохраняя ID и все остальные сведения. Физического удаления через интерфейс нет. Карточки можно редактировать и в архиве; при закрытии изменённой формы предлагается сохранить, отказаться от правок или продолжить работу. После сохранения карточки фильтры переключаются так, чтобы показать и выделить её; после архивирования кнопкой сохраняется выбранный фильтр активности.

Постоянный ID, обозначение редакции и архивный статус позволяют хранить отдельные старые редакции. Обучения ссылаются на программу и сохраняют её снимок при создании: исправления справочника не меняют эти сведения автоматически. Связи с документами пока нет. Полноценное версионирование, правила зачисления, документы и ФИС ФРДО здесь не реализованы; будущие выгрузки должны использовать официальные шаблоны отдельно для ДПО и ПО.

## Учебные группы и обучения (P03.1)

Раздел «Группы» содержит вкладки «Учебные группы» и «Индивидуальное обучение». Группа ссылается на одну существующую активную программу, без обязательного заказчика или договора. Обучение — отдельная запись с постоянным ID, ссылками на слушателя, программу и необязательную группу. Один слушатель может иметь несколько обучений. Состояние `preparation` («Подготовка») не означает юридического зачисления; номера приказов и даты фактического зачисления не создаются.

Плановые даты хранятся как ISO-даты; окончание не раньше начала. Исторические даты допустимы. Отдельное `created_at` устанавливается SQLite в UTC при создании и сохраняется при правках. Возраст проверяется на плановую дату начала существующей функцией `is_adult`, включая достижение 18 лет родившимися 29 февраля с 1 марта невисокосного года. Требования к образованию и юридические основания зачисления здесь не проверяются.

При добавлении в группу её программа и даты подставляются по умолчанию. Даты отдельного обучения можно исправить; изменение дат группы не переписывает уже созданные обучения, о чём сообщает форма. Несовпадение программ запрещено репозиторием и составным отложенным внешним ключом SQLite. Повторный активный состав `(group_id, student_id)` запрещён частичным уникальным индексом. Несколько выбранных слушателей добавляются одной транзакцией; при дубле или ошибке весь набор откатывается. Пересечение периодов одного слушателя по одной программе требует подтверждения, но разрешено.

`program_snapshot` содержит JSON со значениями названия, направления, вида, часов, кода, редакции, квалификации/профессии и разряда. Правки справочника не меняют снимки; обычное сохранение примечания также их не обновляет. На этапе подготовки снимок можно явно обновить в форме. Изменение программы индивидуального обучения требует подтверждения. Изменение программы группы с существующими связями требует отдельного подтверждения и атомарно меняет программу и снимки всех её подготовительных записей, включая исключённые; даты и ID сохраняются. Проверяется отсутствие оформленных записей, возможные пересечения требуют дополнительного подтверждения. После будущей регистрации приказа необходимо сохранять историческое основание и запрещать такие правки; в текущей схеме оформленных состояний нет.

Архивирование и восстановление группы меняют только её активность. Для добавления, правки обучений и исключения сначала нужно восстановить группу. Исключение ошибочно добавленной записи допустимо только при подготовке: состояние `excluded` сохраняет её ID, связи и снимок, скрывая из текущего состава. Включите «Показать исключённые подготовительные записи» для просмотра истории состава. Повторное добавление создаёт новую запись. Основная карточка и другие обучения сохраняются. Физического удаления через интерфейс нет.

Поиск слушателей возвращает только ID, ФИО и дату рождения, максимум 100 совпадений; пустой поиск не загружает весь реестр. Состав и индивидуальный список читают только отображаемые поля, без паспортов и СНИЛС. Формы сохраняют изменения только по явному действию; отмена и отказ от правок не записывают данные. Новых зависимостей и сетевых функций нет. Windows update smoke проверяет сохранность активной/архивной групп, групповых/индивидуального обучений и снимков существующим U01.

## Универсальные DOCX-шаблоны (P03.2)

В **Настройки → Шаблоны документов** работает реестр `document_templates` (миграция № 7). Одна запись — неизменяемая версия: ID, тип, вариант, название, целочисленная версия, относительный путь `templates/<UUID>.docx`, SHA-256, время добавления UTC и активность. Версия назначается в транзакции `BEGIN IMMEDIATE` для точной пары типа и варианта; уникальны номер версии и путь. Частичный уникальный индекс допускает не более одной активной версии пары. Новую версию можно зарегистрировать неактивной; активация старой позволяет вернуться к прежней форме. Деактивация не удаляет файлы.

`TemplateRepository` хранит только проверенный DOCX. Проверка и пробная генерация выполняются до изменения реестра. Файл публикуется перед INSERT и commit; при ошибке SQL новая копия удаляется, прежняя активная версия откатывается. Аварийное завершение между записью файла и commit может оставить непривязанный файл, но не меняет старые версии. Все рабочие файлы получают случайные имена; исходные имена и пользовательские варианты не используются как пути. Символические ссылки и выход за пределы хранилища запрещены. Старые версии не удаляются и не перезаписываются через интерфейс; прямые изменения файла обнаруживаются по SHA-256 при использовании, активации и выгрузке. Это контроль целостности, а не защита SQLite от намеренного изменения владельцем диска.

`docx_context.py` задаёт закрытую схему и вымышленные данные. `docx_engine.py` не зависит от Qt/SQLite: `generate_document(TemplateSource(path, sha256), data, destination)` проверяет хеш и создаёт новый DOCX. Контекст содержит только точные встроенные `dict`, `list`, `str`, `int`, конечный `float`, `bool` и `None`, без подклассов, моделей, функций и путей. Неизвестные ключи, управляющие символы, чрезмерные строки и объём данных отклоняются. `program.name` должен поступать из снимка `program_snapshot.full_name`, `program.hours` — из того же снимка. Подготовка контекста реальных юридических документов будет отдельным сценарием; текущий UI берёт только вымышленные данные и не читает карточки в контекст генератора.

Оформление и структуру Word сохраняет `docxtpl`, работающий через `python-docx` и `lxml`. Язык ограничен поверх `ImmutableSandboxedEnvironment` Jinja: очищены globals/filters/tests, отключены Python-атрибуты и вызовы, отсутствует загрузчик файлов, используется `StrictUndefined` и XML autoescape. До компиляции проверяется AST: разрешены только известные поля, простые условия и один уровень цикла по `students`. Запрещены арифметика, вызовы, фильтры, import/include, макросы, set и доступ к произвольным объектам. Проверяются все ветви, включая неисполняемые, основной текст, колонтитулы, сноски и поддерживаемые основные свойства; теги в неподдерживаемых частях отклоняются. Перед выполнением ограничиваются сложность AST, глубина условий и консервативная оценка объёма результата. Эти ограничения дополняют sandbox, поскольку сам sandbox не ограничивает расход памяти и процессорного времени. Основание: [docxtpl](https://docxtpl.readthedocs.io/en/stable/) и [Jinja sandbox](https://jinja.palletsprojects.com/en/stable/sandbox/).

Пакет DOCX проверяется в памяти без распаковки и разрешения внешних ссылок: ограничения размера/сжатия/числа частей, CRC, обязательные части, закрытый набор имён и типов, корректный XML через `defusedxml` без DTD и сущностей. Все отношения должны быть внутренними и указывать на допустимую часть пакета. Макросы, вложения, OLE/ActiveX, внешние отношения, прямые XML-ссылки на ресурсы, привязки данных, DDE и прочие активные инструкции Word отклоняются; разрешены только поля нумерации страниц. Поддерживаются обычные растровые изображения и инертные customXml-части; неподдерживаемые части отклоняются, а не молча удаляются. Библиотеки не получают разрешения читать внешние файлы или ресурсы шаблона.

Результат полностью формируется и проверяется в памяти, затем записывается во временный файл рядом с назначением, синхронизируется и публикуется без перезаписи. В Windows используется `rename` с отказом при существующем пути, в POSIX — атомарный hard link; при отсутствии поддержки файловой системой операция возвращает ошибку. Неудачная генерация не оставляет частично записанный документ по целевому пути. При аварийном завершении возможен временный `.docx-*.tmp`. Существующие документы не заменяются. Лимиты и синтаксис приведены в [инструкции по шаблонам](templates.md).

Копии для редактирования создаются в `exports/template-edits/`, тестовые документы — в `exports/template-tests/TEST-unregistered-<UUID>.docx`. Внешний редактор запускается только по действию пользователя и только для проверенной локальной копии DOCX, без shell. Для работы требуется установленный обработчик DOCX (Microsoft Word или другой редактор). Тестовая генерация не регистрирует юридические документы и не присваивает юридические номера. Шаблоны и экспортированные файлы находятся вне EXE и переносятся вместе с хранилищем. Механизм U01/S01 и прежние миграции не изменены. Windows smoke дополнен проверкой генерации внутри frozen EXE и сохранности реестра, файлов версий и старого результата при обновлении.

Для следующих этапов сохранены решения: генератор независим от UI, при регистрации юридического документа сохраняются снимки реквизитов слушателя, заказчика, учебного центра и программы. Файлы документов получают путь через `Storage.document_directory` (`documents/YYYY/MM/category/`), номер управляется реестром SQLite отдельно от имени файла. Исторические документы сохраняют исходные даты и номера отдельно от даты внесения; зарегистрированные и подписанные оригиналы не перезаписываются при изменении справочника или шаблона. ДПО и ПО сохраняют отдельные правила. Договоры, заявления, согласия, приказы и протоколы сейчас представлены только типами шаблонов, без юридических текстов, регистрации, зачисления или аттестации. Выпускные документы, ФРДО, подписи, PDF, роли и аудит не реализованы.

## Карточка учебного центра

Откройте **Настройки → Учебный центр**. Это реквизиты вашей образовательной организации, отдельно от реестра организаций-заказчиков. Доступны общие сведения, адреса и контакты, банковские реквизиты, сведения о руководителе и лицензии. Поля необязательны: карточку можно заполнять постепенно. Для введённых ИНН, КПП, ОГРН / ОГРНИП, email, БИК и счетов проверяется формат, без проверки контрольных сумм или обращения к внешним реестрам. Дата лицензии вводится как `ГГГГ-ММ-ДД`.

Изменения реквизитов, загрузка, замена и удаление логотипа применяются только кнопкой **Сохранить**. При уходе из формы, смене раздела или закрытии окна можно сохранить изменения, отказаться от них или отменить выход. Повторное открытие приложения восстанавливает сохранённые данные. В каждой базе допустима только одна карточка (`id = 1`); повторное сохранение обновляет её.

Логотип PNG / JPG ограничен 5 МиБ и 25 млн пикселей; проверяется содержимое изображения. Предпросмотр работает до сохранения. Файл сохраняется в `organization/`, в SQLite хранится относительный путь. Перенос хранилища P01.1 сохраняет доступность логотипа. Новый файл записывается до транзакции SQLite: при ошибке записи реквизитов он удаляется, прежний логотип сохраняется. После успешной замены или удаления привязки прежний файл удаляется; если очистка недоступна, интерфейс сообщает об оставшемся файле. Прерывание питания между записью файла и транзакцией может оставить неиспользуемый файл, не заменяя действующий логотип.

Для будущих документов реквизиты должны браться через `TrainingCenterRepository`. При регистрации документа потребуется сохранять снимок использованных реквизитов: последующие изменения карточки не должны менять зарегистрированные, исторические или подписанные документы. Исторические договоры и приказы могут использовать прежние реквизиты. Изменения карточки в будущем должны учитываться журналом аудита. В P02.1 снимки документов, версионирование, реестры, генерация и аудит не реализуются.

## Основа электронного архива

Единый сервис `Storage.document_directory(document_date, category)` создаёт по запросу путь `documents/YYYY/MM/<category>/`. Принимаются категории `contracts`, `orders`, `protocols`, `issued`, `other`. Год и месяц берутся из даты документа, включая исторические даты; пустые годы и категории заранее не создаются. Интерфейс и будущие генераторы должны получать пути только через этот сервис, а в базе хранить пути относительно корня хранилища.

Правила следующих этапов, которые пока не реализуются:

- Новые договоры, приказы, протоколы и выпускные документы формируются и сохраняются автоматически.
- Номер документа хранится и управляется реестром SQLite, а не именем файла.
- Дата документа и фактическая дата внесения учитываются раздельно. Исторические документы могут сохранять первоначальные номера.
- Существующие документы импортируются через контролируемый интерфейс с указанием категории; непосредственное копирование в архив не заменяет регистрацию.
- Изменения зарегистрированных документов фиксируются в журнале; подписанные оригиналы не перезаписываются.
- Изменения карточек слушателей не изменяют исторические документы автоматически.
- Для бумажных оригиналов предусматривается учёт местонахождения.

P01.1 подготовил основу хранения; P02.1 добавил карточку учебного центра, P02.2 — реестр слушателей. Реестры юридически значимых документов, нумерация, формирование из рабочих карточек, исторический импорт, права доступа и журнал исправлений остаются для следующих этапов. Ранее применённые миграции сохранены без изменений.

## Windows-сборка

Сборка выполняется только в GitHub Actions: при push и pull request либо вручную через **Actions → Windows — тесты и сборка → Run workflow**. [Workflow](../.github/workflows/windows.yml) устанавливает Python 3.12 и фиксированные зависимости, проверяет безопасность и pytest, собирает приложение в режиме PyInstaller onedir и отдельный helper без Qt. Проверяются запуск EXE дважды, создание SQLite и сценарий обновления собранных EXE с сохранением вымышленных данных. Локальную сборку для обычной разработки не выполняем.

Команды сборки из CI (PowerShell):

```powershell
python -m PyInstaller --noconfirm --clean --onedir --windowed --name Proficentr --paths src run_proficentr.py
python -m PyInstaller --noconfirm --clean --onefile --windowed --name ProficentrUpdater --paths src run_updater.py
Copy-Item dist/ProficentrUpdater.exe dist/Proficentr/ProficentrUpdater.exe
```

Затем CI упаковывает всю папку `dist/Proficentr` в `Proficentr-X.Y.Z-Windows.zip`, где версия берётся из приложения, и загружает артефакт `Proficentr-Desktop-Windows` со сроком хранения 14 дней. Обычный workflow не публикует стабильные версии. Как получить и распаковать проверочную сборку — в [README](../README.md#установка); контролируемый выпуск, подпись пакета, защиты GitHub и ограничения проверки — в [updates.md](updates.md#защищённый-выпуск).

Не добавляйте в Git персональные данные, сканы, рабочие базы и секреты; соответствующие файлы и каталоги включены в `.gitignore`. Статус лицензии указан в [README](../README.md#исходный-код-лицензия-и-обратная-связь).
