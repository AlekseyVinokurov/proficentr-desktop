# DOCX-шаблоны

Откройте **Настройки → Шаблоны документов**. Нажмите **Добавить DOCX**, выберите файл, тип, вариант применения и название. Вариант различает формы одного типа, например `dpo`, `po` или `dpo-group`; используйте одинаковое обозначение при регистрации последующих версий. Тип и точный вариант образуют ключ выбора формы. Название служит для отображения.

Программа проверяет файл и формирует пробный результат в памяти. Ошибка не меняет прежние версии. По умолчанию новая версия становится активной; флажок позволяет зарегистрировать её без переключения. Для пары «тип + вариант» может быть активна только одна версия. В таблице видны все версии; выберите старую и нажмите **Активировать версию** для возврата.

Для изменения выберите версию и нажмите **Открыть копию в Word**. Откроется отдельный DOCX в установленном редакторе, оригинал реестра останется в `templates/`. Сохраните правки, затем нажмите **Новая версия** и загрузите изменённую копию. Тип и вариант при этом сохраняются. **Выгрузить копию…** сохраняет файл в выбранное место; существующие файлы программа не заменяет. Редактор Word не входит в приложение.

**Сформировать тестовый документ** создаёт новый файл `exports/template-tests/TEST-unregistered-<ID>.docx` и предлагает открыть его. Используются только вымышленные данные, независимо от содержания вашей базы. Это не зарегистрированный договор, приказ или согласие, у него нет юридического номера. Сформированные файлы не связаны с последующим редактированием шаблона. Изменять содержимое `templates/` вручную нельзя: проверка SHA-256 обнаружит повреждение, используйте выгрузку копии и регистрацию новой версии.

## Одиночные поля

В Word введите тег целиком, со всеми пробелами: `{{ center.full_name }}`. Его можно поместить в обычный текст, ячейку таблицы или колонтитул. Тег наследует оформление участка текста: шрифт, жирность, курсив. Не разбивайте один тег разным форматированием. Обычные изображения вставляйте непосредственно в Word; динамическая вставка файлов не поддерживается.

| Раздел | Доступные поля |
| --- | --- |
| `center` | `full_name`, `short_name`, `inn`, `kpp`, `ogrn`, `legal_address`, `actual_address`, `postal_address`, `phone`, `email`, `website`, `bank_name`, `bik`, `settlement_account`, `correspondent_account`, `director_name`, `director_position`, `director_genitive`, `license_number`, `license_date`, `license_authority` |
| `student` | `full_name`, `surname`, `first_name`, `patronymic`, `birth_date`, `snils`, `citizenship`, `phone`, `email`, `registration_address`, `residential_address`, `passport_series`, `passport_number`, `passport_issued_by`, `passport_issue_date`, `passport_department_code`, `education_level`, `education_document`, `education_details`, `workplace`, `job_title` |
| `customer` | `full_name`, `short_name`, `kind`, `inn`, `kpp`, `ogrn`, `legal_address`, `actual_address`, `postal_address`, `phone`, `email`, `bank_name`, `bik`, `settlement_account`, `correspondent_account`, `representative_name`, `representative_position`, `authority_basis`, `power_of_attorney`, `birth_date`, `registration_address`, `passport_series`, `passport_number`, `passport_issued_by`, `passport_issue_date`, `passport_department_code` |
| `program` | `name`, `direction`, `kind`, `hours`, `code`, `edition`, `qualification`, `grade` |
| `training` | `start_date`, `end_date`, `state` |
| `document` | `number`, `date`, `is_test`, `is_draft` |
| `contract` | `total_price`, `payment_terms`, `currency`, `student_count` |
| `group` | `name`, `start_date`, `end_date` |

Составное поле записывается через точку: `{{ program.hours }}`. Даты передаются готовыми строками; в тесте используется `ГГГГ-ММ-ДД`. Направление в тестовых данных — `dpo`, вид — `dpo_upskilling`. Число часов — число. Поле `document.is_test` — логическое значение. Отсутствующие обязательные значения вызывают ошибку генерации; необязательное поле следует передать пустой строкой. Полный список есть и в приложении по кнопке **Доступные поля**.

## Условия

Простое условие внутри абзаца:

```text
{% if customer.full_name %}Заказчик: {{ customer.full_name }}{% else %}Заказчик не указан{% endif %}
```

Для условного абзаца создайте три отдельных абзаца Word:

```text
{%p if document.is_test %}
Тестовый документ. Не зарегистрирован.
{%p endif %}
```

Служебные абзацы исчезнут из результата. Разрешены `if`, `elif`, `else`, `endif`, `not`, `and`, `or`, сравнения `==` и `!=` поля с постоянной строкой, числом или логическим значением. Например: `{% if program.direction == 'dpo' %}`. Другие выражения, фильтры и функции запрещены.

## Список слушателей

Создайте таблицу с заголовком и тремя строками ниже:

| Первая ячейка | Вторая ячейка |
| --- | --- |
| `{%tr for row in students %}` | Оставьте пустой |
| `{{ row.full_name }}` | `{{ row.start_date }}` |
| `{%tr endfor %}` | Оставьте пустой |

Средняя строка повторится для каждого слушателя, а две служебные строки исчезнут. Внутри цикла доступны все поля `student` и дополнительные `start_date`, `end_date` через переменную `row`. Можно добавить нужные столбцы. Условия внутри повторяемой строки допустимы. Вложенные циклы, фильтрация цикла и `loop.index` не поддерживаются. Список может содержать до 500 записей; пустой список удаляет повторяемую строку.

## Ограничения формата

Принимается обычный DOCX: до 10 МиБ в архиве, до 32 МиБ после распаковки, до 8 МиБ на часть и до 1000 частей. Чрезмерное сжатие и сложность XML/шаблона отклоняются. Данные ограничены 1 МиБ, строка — 10 000 знаков, вычисляемый объём результата — 16 МиБ XML; большие формы могут потребовать разделения.

Разрешены обычный текст, таблицы, колонтитулы, сноски и встроенные растровые изображения PNG/JPEG/GIF/BMP/TIFF. Макросы, OLE/ActiveX, вложенные документы, внешние гиперссылки и связанные изображения, поддокументы, динамические изображения, SVG/EMF/WMF, графики, нестандартные части пакета и DTD/сущности XML отклоняются. Из инструкций Word разрешены только `PAGE`, `NUMPAGES`, `SECTIONPAGES` (возможен `\* MERGEFORMAT`); другие автоматические поля, включая DDE, запрещены. Ссылки можно оставить обычным текстом без внешнего отношения Word. При отказе удалите неподдерживаемые элементы и сохраните обычный DOCX.

Шаблоны не получают доступа к файлам, функциям Python, моделям приложения или базе. Юридические тексты, их утверждение и применимость остаются ответственностью учебного центра. Для договоров P03.3 доступны реальные сведения, регистрация и нумерация. Зачисление, подписи, PDF и ФРДО отсутствуют.


## Договоры с реальными сведениями (P03.3)

Для договора тип шаблона определяется по заказчику: `contract_person` для слушателя или другого физлица, `contract_legal` для организации, `contract_entrepreneur` для ИП. Вариант должен быть точно `dpo` или `po` либо начинаться с `dpo-` / `po-` соответственно направлению снимка программы. Это соглашение о настройке реестра; произвольный `default` не выбирается автоматически. Суффикс различает ваши формы, например `dpo-group`. Он не выполняет юридическую проверку формы. Если активных подходящих вариантов несколько, сотрудник явно выбирает один. Неактивные версии и другое направление не используются для новой регистрации. Для настройки нового варианта можно выгрузить копию и добавить её в реестр с нужным обозначением.

Контекст договора берёт `program.name`, часы, вид, квалификацию и редакцию из снимка обучения. Текущее название в справочнике может отличаться. Выбранные обучения должны ссылаться на одну программу и одинаковый снимок редакции; при различии оформите отдельные договоры либо явно исправьте подготовительные записи. Лимит — 500 обучений. Договор не меняет состояния обучения.

`contract.total_price` — готовая точная строка в рублях с двумя знаками после запятой, например `123,45`; `contract.currency` — `RUB`; `contract.payment_terms` — введённый текст, в том числе оплата по счёту или взаимозачёт. Это общая стоимость договора, а не цена на одного слушателя. Нулевая стоимость допускается. `contract.student_count` — число разных слушателей.

В `students` одна строка на выбранное обучение, со своими `start_date` и `end_date`. При нескольких обучениях одного человека ФИО может повторяться. `student` заполняется только для одного выбранного обучения; для нескольких используйте таблицу `students`. `training.start_date` / `end_date` содержат значение только при совпадении соответствующих дат у всех выбранных обучений; иначе передаётся пустая строка. `group` заполнен только при общей группе для всего выбранного состава. Реквизиты стороннего заказчика берутся из карточки договора, слушателя-заказчика — из его существующей карточки; работодателем заказчик автоматически не становится.

**Тестовый документ** в настройках остаётся полностью вымышленным (`document.is_test = true`). **Проект договора** содержит реальные сведения (`is_test = false`, `is_draft = true`), не занимает номер и сохраняется в `exports/contract-drafts/`. Приложение добавляет в начало видимую отметку «ПРОЕКТ ДОГОВОРА — НЕ ЗАРЕГИСТРИРОВАН», даже если шаблон не использует номер. Для условного оформления можно использовать `{% if document.is_draft %}`. Перед регистрацией сотрудник проверяет проект. Изменение черновика, реквизитов, обучений или подходящей версии шаблона требует нового проекта.

После подтверждения регистрации `document.number` содержит окончательный номер, `document.date` — исходную дату договора, `is_draft = false`. Окончательный файл формируется заново в `documents/YYYY/MM/contracts/`; сохраняются SHA-256 и снимок использованных данных. Открытие через приложение выдаёт проверенную копию, не оригинал. Активность шаблона или изменения справочников больше не меняют этот файл. Подписание этим действием не подтверждается. Пользовательские формы перед эксплуатацией должны быть проверены на соответствие применимым требованиям и локальным актам; программа такой юридической проверки не выполняет.


## Приказы о зачислении (P03.4)

Тип — `enrollment_order`. Используйте варианты `dpo-individual`, `dpo-group`, `po-individual`, `po-group`; дополнительный суффикс через дефис различает свои формы. Для нового приказа выбирается активная версия нужного направления из снимка программы и вида приказа. При нескольких подходящих вариантах нужен явный выбор. Утверждение форм и проверка применимых требований остаются за организацией.

Контекст содержит `center`, `program`, `document`, `training`, `group`, `students`, а также `order.kind` (`individual`/`group`) и `order.student_count` (количество выбранных обучений). `student` заполнен при одном обучении. Поля заказчика/стоимости не заполняются: у слушателей одного приказа могут быть разные договоры и заказчики. Направления ДПО/ПО и их структурированные виды сохраняются отдельно, одинаковых образовательных условий программа не устанавливает.

В `students` одна строка на выбранное обучение: ФИО и прочие разрешённые сведения слушателя, собственные `start_date` / `end_date`. Пример строк таблицы Word:

```jinja
{%tr for row in students %}
{{ row.full_name }} | {{ row.start_date }} | {{ row.end_date }}
{%tr endfor %}
```

Если периоды различаются, даты `training` и `group` пустые. До регистрации проверяется наличие вывода обеих дат внутри цикла `students`; форму без такого вывода нужно исправить. Окончательный макет сотрудник проверяет в проекте DOCX.

Проект хранится в `exports/order-drafts/`, имеет `document.is_draft = true`, не занимает номер и содержит добавленную приложением видимую отметку «ПРОЕКТ ПРИКАЗА — НЕ ЗАРЕГИСТРИРОВАН». Изменение источников после просмотра требует нового проекта. Регистрация назначает номер/исторический номер и формирует окончательный файл в `documents/YYYY/MM/orders/`, фиксируя данные, версию формы и SHA-256. Подтверждение подписания выполняется отдельно и не меняет DOCX; фиктивных подписей, печатей и электронной подписи нет. Открытие выдаёт проверенную копию. Для исправления основания после регистрации нужен новый приказ; произвольной отмены подписанного приказа пока нет.

## Протоколы аттестации (P04.1)

В **Документы → Протоколы аттестации** используются только активные формы `protocol_dpo` (итоговая аттестация ДПО) или `protocol_po` (квалификационный экзамен ПО). При нескольких активных вариантах сотрудник выбирает нужную форму. Если её нет, загрузите собственный DOCX в настройках. Программа не поставляет окончательные юридические формы: перед реальной эксплуатацией их необходимо отдельно проверить и согласовать с учётом применимых требований и локальных актов.

Поля протокола: `protocol.number`, `protocol.date`, `protocol.attestation_date`, `protocol.kind`, `protocol.chair`, `protocol.members`, `protocol.note`. Поля `document.number` и `document.date` также доступны. `program` содержит снимок программы из обучения, `center` — реквизиты центра, `group` — сведения группы. При различающихся периодах общие даты пустые: выводите даты каждого обучения в таблице.

В повторяющихся строках `students` доступны ФИО и остальные поля слушателя, `row.start_date`, `row.end_date`, а также:

| Поле | Содержание |
| --- | --- |
| `row.attestation_result` | Успешно прошёл / Не прошёл / Не явился; пустая строка, если не указан |
| `row.grade` | Оценка в свободной форме, если применяется |
| `row.qualification` | Указанная сотрудником квалификация, профессия или должность |
| `row.qualification_grade` | Разряд или категория, если применяется |
| `row.attestation_note` | Индивидуальное примечание |

Пример содержимого строки таблицы между служебными строками `{%tr for row in students %}` и `{%tr endfor %}`:

```jinja
{{ row.full_name }} | {{ row.start_date }} — {{ row.end_date }} | {{ row.attestation_result }} | {{ row.grade }} | {{ row.qualification }} | {{ row.qualification_grade }}
```

Предварительный DOCX получает видимую отметку проекта независимо от наличия условия в форме и не занимает номер. После регистрации состав, результаты, снимок и версия формы фиксируются. Регистрация сама по себе не подтверждает подписание; подтверждение выполняется отдельно и не добавляет подписи или печати в DOCX.

## Приказы о завершении обучения (P04.2)

В **Документы → Приказы о завершении** используется загруженный пользователем активный шаблон типа `completion_order`. Точные варианты: `dpo-individual`, `dpo-group`, `po-individual`, `po-group`. Программа подбирает форму по направлению из снимка обучения и виду приказа. При отсутствии формы загрузите её через кнопку **Открыть настройки шаблонов** в карточке приказа. Юридические тексты приказов не поставляются: организация должна отдельно проверить формы, применимые требования и локальные акты.

Номер и дата приказа — `document.number` и `document.date`; вид приказа и число слушателей — `order.kind`, `order.student_count`. Сведения о программе, направлении и виде — `program.name`, `program.direction`, `program.kind` и остальные поля `program`. Реквизиты центра и руководителя доступны в `center`.

| Поле | Назначение |
| --- | --- |
| `completion.date` | Общая фактическая дата завершения, только если одинакова для всех включённых обучений |
| `completion.basis` | Общее текстовое основание, только если одинаково для всех |
| `row.completion_date` | Фактическая дата завершения конкретного обучения |
| `row.completion_basis` | Вид аттестации, номер и дата конкретного протокола |
| `row.protocol_number`, `row.protocol_date` | Номер и дата протокола-основания |
| `row.attestation_date` | Дата аттестации-основания |
| `row.attestation_result`, `row.grade` | Подтверждённый успешный результат и оценка, если указана |
| `row.qualification`, `row.qualification_grade` | Квалификация/профессия/должность и разряд/категория из подписанного результата |
| `row.start_date`, `row.end_date` | Исходные плановые даты обучения |

При одном общем протоколе доступны также `protocol.number`, `protocol.date`, `protocol.attestation_date`, `protocol.kind`; если основания различаются, общие поля протокола пустые. Для групповых форм выводите основания каждого слушателя в строках `students`. Пример строки между `{%tr for row in students %}` и `{%tr endfor %}`:

```jinja
{{ row.full_name }} | {{ row.completion_date }} | {{ row.completion_basis }} | {{ row.attestation_result }} | {{ row.qualification }} | {{ row.qualification_grade }}
```

Различающиеся фактические даты не подменяются датой группы или приказа: общее поле пустое, а шаблон обязан выводить `row.completion_date` в цикле `students`, иначе генерация отклоняется. Поля дат передаются в формате `ГГГГ-ММ-ДД`. Квалификация не выводится из названия программы и не присваивается автоматически.

Проект получает видимую отметку независимо от содержимого формы и не занимает номер. Регистрация фиксирует DOCX и снимок, но не завершает обучение. Подтверждение подписания и условий выполняется отдельно; оно не добавляет подписи, печати или выпускные документы в DOCX. После регистрации правки требуют нового оформления.

## Выпускные документы (P04.3)

Загрузите собственные утверждённые формы через **Настройки → Шаблоны документов**. Поддерживаются типы `dpo_upskilling_certificate` (удостоверение ДПО), `dpo_retraining_diploma` (диплом ДПО), `po_profession_certificate` (свидетельство ПО). Вид определяется по структурированному виду программы из исторического завершения, а не по названию. Активная версия выбирается внутри соответствующего типа; при нескольких активных вариантах сотрудник выбирает форму в строке документа. Готовые юридические формы организации не поставляются.

Каждый завершённый слушатель получает отдельный DOCX. В групповом оформлении даты и бланки проверяются отдельно по каждой строке. ФИО, программа, академические часы, реквизиты центра и руководителя берутся из снимка подписанного приказа о завершении. Позднейшие изменения справочников не подставляются автоматически. `student` содержит исторические сведения одного слушателя, `program` — историческую программу, `center` — исторические реквизиты центра. `students` содержит только этого слушателя; общий выпускной DOCX на группу не создаётся.

| Поле | Содержание |
| --- | --- |
| `issued.kind` | Наименование вида выпускного документа |
| `issued.number`, `issued.date` | Регистрационный номер и дата документа |
| `issued.blank_series`, `issued.blank_number` | Серия и номер фактического бланка, если заполнены |
| `issued.completion_date` | Фактическая дата завершения обучения |
| `issued.completion_order_number`, `issued.completion_order_date` | Реквизиты подписанного приказа о завершении |
| `issued.qualification`, `issued.qualification_grade` | Квалификация/профессия/должность и разряд/категория из основания завершения |

Также доступны `document.number`, `document.date`, `student.full_name`, `program.name`, `program.hours`, `program.direction`, `program.kind` и остальные прежние поля. Квалификация не выводится из названия программы. Серия и номер бланка не равны регистрационному номеру автоматически; их вводят по имеющемуся физическому бланку. Пустая серия допустима. Проект имеет видимую отметку независимо от текста шаблона и не занимает номер. После регистрации DOCX, снимок и версия формы защищены от обычного изменения. Регистрация не подтверждает передачу оригинала.
