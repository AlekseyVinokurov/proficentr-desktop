# ФИС ФРДО: шаблоны, подготовка сведений и XLSX (P05.1–P05.3)

## Подключение сотрудником

В «Настройки → ФИС ФРДО» независимо подключаются XLSX ДПО и ПО. После проверки файл копируется в `templates/<uuid>.xlsx` внутри выбранного локального хранилища. Исходные байты не пересохраняются библиотекой Excel. SHA-256, исходное имя, дата подключения, вид и последовательная версия хранятся в SQLite (миграция № 13, таблица `frdo_templates`). Интерфейс показывает активную версию и контрольную сумму; при открытии проверяет файл повторно.

Замена сначала проверяет файл, затем создаёт отдельную копию с fsync и проверкой байтов. Активная версия переключается в транзакции `BEGIN IMMEDIATE`; при ошибке записи или SQL выбор откатывается, незавершённая копия удаляется. Все прежние файлы и версии сохраняются. При аварийном завершении между записью и commit возможна неактивная копия без записи в реестре; предыдущий активный файл остаётся целым. Автоматическое удаление истории и переключение старых версий через UI в этот этап не входят. Перенос хранилища существующим механизмом переносит и файлы, и относительные ссылки в SQLite.

## Исходные материалы и проверенная структура

Использованы предоставленные `references/frdo/dpo_template.xlsx`, `po_template.xlsx` и две инструкции PDF. Их происхождение и актуальность на портале автоматически не подтверждены. Каталог `references/frdo/` целиком исключён из Git, включая метки Windows Zone.Identifier. Код содержит только структурные профили, документацию и искусственные тестовые данные.

| Элемент | ДПО | ПО |
| --- | --- | --- |
| SHA-256 предоставленного XLSX | `3824efc21a11a3d57ea946684d4cd97d55f7b3c10b7d66dae7041248f3135fcd` | `13f0c83e1c568fb0f728c5ebe51351e902e8a93e84b97aaaa1e4767b19a86407` |
| Лист данных | `Шаблон`, видимый, A–AN | `Шаблон`, видимый, A–AI |
| Заголовки / строки данных | 1 / 2–1001 | 1 / 2–1002 |
| Справочники | скрытый `Проверки` | скрытый `Проверки` |
| `Таблица1` | **на листе Проверки**, B1:J34 | **на листе Проверки**, A1:G83 |
| Именованные диапазоны | 14 | 13 |
| Проверки данных / из них списки | 22 / 15 | 20 / 13 |

Проверка профиля сопоставляет все заголовки, порядок, размеры, состояния листов, определения именованных диапазонов, типы, диапазоны и формулы dataValidation, таблицу и наличие форматов. OOXML разбирается безопасным XML-парсером; макросы и внешние связи отклоняются, размеры ZIP ограничены. Таблица проверяется также в исходном OOXML. Контроль сохранности после подключения сравнивает все части ZIP (включая workbook, relationships, styles, worksheets и tables), а также полные байты и SHA-256. Листы не добавляются, штатный скрытый лист не удаляется.

Профили намеренно соответствуют этим двум файлам. Другие редакции с изменёнными заголовками, именами, диапазонами или проверками потребуют явной адаптации профиля и правил. Изменение значений в поддерживаемых диапазонах само по себе не требует изменения интерфейса.

## Справочники конкретного файла

`inspect_template` возвращает `TemplateStructure.dictionaries`: буква столбца → точные строковые значения. Источник — формула проверки данных на листе `Шаблон`, далее именованный диапазон на `Проверки`. Для ДПО L используется структурированная ссылка `Таблица1[[ Наименование области профессиональной деятельности]]`; начальный пробел в имени колонки существенен. Пустые ячейки не становятся допустимыми значениями. Формулы в значениях справочников не вычисляются и отклоняются.

Примеры: статус `Оригинал`, пол `Муж`/`Жен`, гражданство строковыми кодами `000`, `004`, `643`; форма `Очная`, `Очно-заочная (вечерняя)`, `Заочная`; финансирование `Федеральный бюджет`, `Региональный бюджет`, `Местный бюджет`, `Платное обучение`. Полные справочники читаются из подключённой версии, не подменяются этими примерами. Числовые значения квалификационных разрядов ПО приводятся к строкам; коды гражданства в исходных XLSX уже строковые и сохраняют нули.

`PreExportValidator` допускает явные сопоставления `mappings={"dpo": {"Z": {"male": "Муж"}}, "po": {"U": {...}}}`. Результат сопоставления повторно проверяется по текущему справочнику. Без соответствия значение отклоняется, ошибка предлагает точные варианты (в том числе исправление регистра). Автоматического выбора похожего варианта нет. Регистр, пробелы и написание точного значения справочника сохраняются; справочник не меняется.

## Соответствия полей

Это подтверждённые места назначения для будущего адаптера модели; автоматическая выгрузка записей SQLite на P05.1 не выполняется.

| Сведения | ДПО | ПО | Источник / ограничение внутренней модели |
| --- | --- | --- | --- |
| Вид, статус | A, B | A, B | `IssuedDocument.kind` соответствует одному из трёх поддерживаемых видов; обычный статус `Оригинал` |
| Утрата, обмен, уничтожение | C–E | C–E | Для обычного оригинала `Нет`; специальные операции не реализованы |
| Серия, номер бланка | F, G | F, G | `IssuedDocument.blank_series`, `blank_number`; только фактически выданный документ |
| Дата выдачи, рег. номер | H, I | H, I | `IssuedDocument.document_date`, `number`; исторические реквизиты требуют согласования адаптера |
| Вид программы, название | J, K | J, K | Структурированный `program_kind`, `program_name` из снимка; ПО требует отдельных точных соответствий |
| Область деятельности, укрупнённая группа | L, M | — | В текущей модели нет отдельных классификаторов |
| Квалификация | N | L | ДПО — `qualification`; ПО L — классификатор профессий `Квалиф`, свободного текста недостаточно |
| Разряд, класс, категория | — | M | `qualification_grade`, обязательное точное соответствие справочнику при заполнении |
| Предыдущее образование | O–R | — | В Student есть `education_level`, `education_document`, `education_details`; свободные сведения нельзя однозначно разложить на фамилию, серию и номер |
| Годы начала, окончания; часы | S, T, U | N, O, P | Годы обучения из подтверждённого обучения; `hours` из снимка; не дата запуска программы |
| Фамилия, имя, отчество | V, W, X | Q, R, S | Отдельные поля Student / снимка; `full_name` нельзя надёжно разделять автоматически |
| Дата рождения | Y | T | `birth_date`; явное преобразование ISO в ДД.ММ.ГГГГ |
| Пол | Z | U | В текущей модели Student отдельного поля нет; нельзя угадывать по ФИО |
| СНИЛС | AA | V | `snils`; явное форматирование 11 цифр в ХХХ-ХХХ-ХХХ ХХ будущим адаптером |
| Форма обучения, финансирование, форма получения образования | AB–AD | X–Z | Отдельных подтверждённых полей текущей модели недостаточно; нужны данные/сопоставления следующего этапа |
| Гражданство | AE | W | `citizenship` сейчас свободный текст; требуется подтверждённый код ОКСМ, отсутствие гражданства — `000` |
| Сведения об оригинале для дубликата | AF–AM | AA–AH | На этом этапе пустые, дубликаты не реализованы |
| Номер документа для изменения | AN | AI | При обычном экспорте всегда пустой |

Расхождения источников: PDF ДПО обозначает серию и номер ВО/СПО как S, а год начала обучения как R. В XLSX это Q, R и S соответственно; реализация следует фактическим заголовкам XLSX. Пример вида программы в PDF ДПО содержит «Профессиональная подготовка», тогда как XLSX — «Профессиональная переподготовка». PDF ПО описывает L как область деятельности, фактический XLSX содержит профессии рабочих/должности служащих. Примеры формы получения образования в PDF начинаются с заглавной буквы, значения XLSX — со строчной. Для списков используются точные значения XLSX; эти расхождения не исправляются в исходных файлах.

## Нормализация и предэкспортная проверка

Сервис принимает идентификатор записи и словарь значений по буквам столбцов. Возвращает подготовленную копию, список изменений и ошибки с записью, полем, исходным значением, причиной и предлагаемыми вариантами. Исходный словарь и SQLite не меняются. Значения реквизитов и кодов передаются строками: числовой ввод отклоняется, поскольку нули могли быть потеряны. Объекты date/datetime преобразуются в ДД.ММ.ГГГГ.

В обычном тексте U+00A0, U+202F, табуляция и переносы заменяются пробелами; крайние и повторные пробелы нормализуются. Существенные символы ФИО/программ сохраняются. Серии, номера и регистрационные реквизиты автоматически не исправляются: сомнительные пробелы требуют подтверждения. U+200B, U+FEFF, управляющие/непечатные символы, другие запрещённые пробелы выявляются ошибкой. Похожие латинские буквы в кириллическом ФИО не заменяются, содержательные знаки программ не удаляются. Точные значения справочника сохраняются даже с необычными пробелами. Затем повторно проверяются ограничения поля.

Правила по двум PDF, сверенные с XLSX:

- Обязательны A–E, H, I, K, годы, часы, ФИО и пол. F/G обязательны, кроме справки об обучении. Отсутствие отчества обозначается `Нет` явно; пустое отчество не подменяется автоматически. В ДПО обязательна квалификация N (если не присвоена, PDF допускает `Нет`). В ПО обязательна профессия L, кроме свидетельства по программам в области искусств; для него J/L должны быть пустыми.
- Начиная с года выдачи 2021 обязательны дата рождения, гражданство, форма обучения, финансирование, форма получения образования. При гражданстве `643` обязателен СНИЛС. Для более ранних выдач эти поля могут отсутствовать; заполненные значения всё равно проверяются.
- СНИЛС: формат ХХХ-ХХХ-ХХХ ХХ, ненулевой номер и существующая проверка контрольной суммы приложения; для старых номеров до 001-001-998 включительно проверяется формат без контрольной суммы, как в общей модели слушателя. Пример PDF `123-456-789 10` проверку суммы не проходит и не используется как корректный номер.
- ФИО: кириллица, допустимые PDF знаки, до 50 символов, запрет дефисов на краях и соседних пробелов/дефисов. Серия до 20, номер до 40, регистрационный номер до 30 символов; разрешённые знаки регистрационного номера различаются ДПО/ПО (в ПО также `№` и `_`). Программа: ДПО до 600, ПО до 255; квалификация ДПО до 500. Даты строго ДД.ММ.ГГГГ, существующие; дата рождения не позже выдачи, выдача не в будущем.
- Для оригиналов годы от 1978 до переданного текущего года, окончание не раньше начала и не позже года выдачи. Часы — положительное целое, ПО не менее 6. Все заполненные списки должны точно соответствовать XLSX. Сведения о дубликатах и поле изменения отклоняются для обычного экспорта.

Сервис сам по себе не подтверждает фактическую выдачу документа и достоверность реквизитов. Будущий адаптер должен использовать зарегистрированный документ и согласованные снимки, а отсутствующие сведения показывать сотруднику.

## Имя будущего файла

`export_filename(ogrn, kpp, issue_year, number)` проверяет 13 цифр ОГРН, 9 цифр **КПП**, четырёхзначный год выдачи и положительный целый номер. Пример: `1125900003360_590301001_26_9.xlsx`. Год передаётся явно; текущая дата для имени не используется. Функция ничего не резервирует и не создаёт файл.

Устойчивый счётчик организации/года, единая последовательность ДПО/ПО, отсутствие перезаписи, повторное скачивание того же пакета и повторы после ошибок будут реализованы вместе с экспортом. Предпросмотр не должен резервировать номер.

## Проверки и границы

Локальные тесты читают именно предоставленные XLSX и проверяют SHA-256, структуру, справочники и побайтовую сохранность после подключения. При отсутствии файлов эти два теста явно пропускаются. CI использует отдельные искусственные XLSX с теми же структурными профилями и вымышленными значениями; они не являются заменой исходных эталонов или готовыми файлами ФРДО. Тесты сравнивают OOXML, проверяют повреждения, неудачные замены, независимость ДПО/ПО, перезапуск, миграцию, нормализацию, словари, СНИЛС и имя. Windows smoke проверяет чтение подключённых искусственных шаблонов в собранном EXE и сохранение после обновления.

Полного заполнения реестров, загрузки на портал, учёта статусов, дубликатов и сложных исправлений нет. До реального пробного импорта остаются проверка актуальности шаблонов, завершение адаптера внутренних данных (особенно пол/форма/финансирование/классификаторы/образование), сверка серверных ограничений и подтверждение приёма. Успешное чтение XLSX и локальные проверки **не гарантируют приём сервером ФИС ФРДО**.

## Подготовка сведений (P05.2)

В разделе **Документы → Подготовка ФРДО** выберите ДПО/ПО и период **выдачи** документов, затем нажмите «Проверить готовность». В список попадают только зарегистрированные основные выпускные документы выбранной категории. Одна строка соответствует одному документу одного обучения. Состояния — «Готово» и «Требует исправления»; это только локальная проверка. При выборе строки показываются ошибки с ФИО и понятными названиями полей, без необходимости искать столбец Excel. «Открыть сведения и исправить» открывает единую форму с тремя вкладками. После сохранения и при повторном входе список пересчитывается; изменение категории/периода сбрасывает прежние результаты.

### Источники и хранение

Миграция № 14 добавляет только неизвестные по умолчанию строки и две компактные таблицы. Прежние значения и защищённые документы не обновляются.

| Сведения | Источник P05.2 / место сохранения |
| --- | --- |

| Название, вид программы, часы, квалификация и фактически присвоенный разряд | Зафиксированные поля зарегистрированного документа, происходящие из подписанного завершения и аттестации; текущая редакция программы их не заменяет |
| Вид программы J | Явное раздельное соответствие структурированных видов `dpo_upskilling`/`dpo_retraining` и `po_initial_training`/`po_retraining`/`po_upskilling` точным строкам XLSX; результат проверяется по подключённому справочнику |
| Годы | Начало из `snapshot.basis.training.start_date` именно этого обучения; окончание из фактического `IssuedDocument.completion_date` подписанного завершения, а не из планового срока другого обучения |
| Область деятельности и укрупнённая группа ДПО, профессия ПО | Новые `Program.dpo_area`, `dpo_group`, `po_profession` записываются в снимок **нового** обучения, если известны. Адаптер читает снимок внутри выпускного документа. Для прежних снимков есть явные уточнения этих классификаторов в `frdo_training_details` данного обучения. | Квалификация ДПО, не заполненная в старом документе | Явное уточнение `frdo_training_details.qualification`; только при отсутствии исходного значения. `Нет` сотрудник вводит сам после проверки; заполненная квалификация документа не подменяется |
| Форма обучения, финансирование, получение образования | `frdo_training_details.form`, `funding`, `relations` — условия конкретного обучения; не выводятся из договора, дистанционных технологий или программы |
| Предыдущее образование ДПО | `frdo_training_details.education_level`, `education_surname`, `education_series`, `education_number` — сведения при поступлении на это обучение. Для уровня при отсутствии уточнения используется только историческое `snapshot.context.student.education_level`, не текущая карточка. Свободный `education_details` автоматически не разбирается |
| Дубликаты и изменения | Все соответствующие столбцы остаются пустыми; статус `Оригинал`, подтверждения C–E — `Нет` для обычного выпуска |

Вкладка **«Это обучение»** уточняет конкретную историческую запись. Вкладка **«Программа: новые обучения»** отдельно изменяет три классификатора текущей карточки программы для будущих снимков. Она не обновляет старые снимки и готовность уже выданных документов автоматически. Пустые классификаторы не добавляются в новые снимки, поэтому существующие подготовительные записи остаются совместимы с новыми при неизвестных значениях. Существующие карточки слушателя/программы сохраняют дополнительные поля при обычном редактировании. Формы DOCX и разрешённый набор их переменных не расширялись: новые классификаторы сохраняются в снимке, но не передаются в контекст бланков.

### Проверка, справочники и защита

Адаптеры `adapt_dpo` и `adapt_po` формируют все 40/35 столбцов, включая пустые поля дубликатов/исправлений. Готовность определяет существующий `PreExportValidator`; отдельного второго валидатора нет. При сохранении дополнений используются его же правила соответствующего поля и точные справочники активного XLSX. Неполную карточку можно сохранять по мере заполнения; введённое недопустимое значение отклоняется. Нормализация применяется к подготовленной копии, исходные реквизиты защищённого реестра не меняются.

Списки берутся из подключённого XLSX с поиском по подстроке. Коды ОКСМ сохраняются строками с ведущими нулями. У предоставленных шаблонов справочник гражданства содержит только коды, без названий стран; для `000` интерфейс поясняет «Без гражданства», для `643` — «Российская Федерация», прочие коды показывает как в исходном справочнике. Код не выбирается из адреса или свободного описания гражданства. Пол, форма и финансирование не угадываются. Слово `Нет` не подставляется вместо неизвестной квалификации/отчества автоматически.

`PreparedRecord` содержит неизменяемую последовательность пар «столбец–значение», ошибки, идентификаторы документа/обучения/слушателя, версию и SHA-256 шаблона, отпечаток исходных сведений. Получение `.values` создаёт отдельный словарь. Проверка каждый раз читает источники заново. Форма передаёт отпечаток при сохранении; изменение исходных сведений или активной версии шаблона отклоняет устаревшую правку и требует повторного открытия записи. Изменения карточки программы сами по себе не подменяют значения исторической строки.

Дополнения записываются единой транзакцией `BEGIN IMMEDIATE`. Таблица `frdo_change_history` хранит контекст документа, время UTC и изменённые поля (уровень сущности, идентификатор, старое/новое значение). UPDATE, DELETE и подмена существующего события через REPLACE блокируются триггерами. Единого аудита обычных карточек в проекте нет; эта история покрывает изменения через форму подготовки ФРДО, а не произвольные изменения SQLite или правки прежних полей в других разделах. Автор операции не определяется: учётных записей сотрудников пока нет. Это локальная история изменений, не защита базы от копирования или прямого редактирования вне приложения.

При подготовке не выполняются UPDATE зарегистрированных документов, изменение их снимков, регенерация или замена файлов. Отсутствующие/недопустимые серия, номер, ФИО или иные уже зафиксированные значимые реквизиты показываются как ошибки; безопасный процесс исправления таких выданных документов остаётся за пределами P05.2. Дополнения не доказывают достоверность сведений: сотрудник сверяет их с первичными документами.

### Границы P05.2

Заполненный XLSX не создаётся, номер выгрузки не резервируется, портал не вызывается, статусы приёма не ведутся. P05.3 должен формировать пакет по повторно проверенному стабильному представлению, сохраняя структуру эталона, и реализовать устойчивую последовательность выгрузок. Реальный пробный импорт и подтверждение приёма ФИС ФРДО по-прежнему не выполнены.

## Формирование и журнал XLSX (P05.3)

В «Документы → Подготовка ФРДО» выберите категорию и период, нажмите «Проверить готовность», выделите строки (Ctrl/Shift либо «Выбрать готовые») и «Сформировать XLSX». Весь выбранный набор должен пройти проверку. Ошибки одной строки блокируют весь запрос. Набор ограничен одной категорией, годом выдачи и историческими ОГРН/КПП организации из снимков выданных документов. Эти реквизиты не заменяются текущей карточкой центра; отсутствие 13 цифр ОГРН или 9 цифр КПП требует проверки исторического основания. Автоматического исправления защищённых снимков нет.

`FrdoExportRepository` повторно читает зарегистрированные документы и источники, активную версию/байты шаблона, запускает существующий адаптер и `PreExportValidator`, сравнивает все `PreparedRecord`, включая отпечатки и значения. Проверка выполняется под `BEGIN IMMEDIATE`, поэтому конкурентные изменения SQLite не проходят между проверкой и регистрацией. Устаревшие сведения требуют повторной проверки. Исходный XLSX повторно сверяется с SHA-256 перед commit. Экспорт не меняет карточки, зарегистрированные документы, снимки или архивные DOCX.

`fill_xlsx` изменяет только XML элемента `sheetData` листа «Шаблон» в копии исходного ZIP. Прочие части OOXML сохраняются побайтно, включая справочники, имена, таблицу, styles, relationships, служебные формулы и расширения. Внутри листа сохраняются заголовки, атрибуты строк/ячеек и стили; вне `sheetData` остаются исходные байты. Формула внутри области ввода блокирует неподдерживаемый шаблон, а не затирается. Все строки данных очищаются от прежних значений перед заполнением выбранных строк. Файл повторно проверяется по структурному профилю P05.1; служебные части сравниваются с оригиналом.

Серии, регистрационные номера, СНИЛС, коды и прочий текст записываются как `inlineStr`, поэтому ведущие нули и строки с `=`, `+`, `-`, `@` не становятся числами/формулами. Даты преобразуются только из проверенного представления ДД.ММ.ГГГГ в числовую дату Excel с учётом системы дат книги; годы и часы — в числа. Используются исходные форматы официального XLSX. Правила полей заново в писателе не вычисляются. ДПО заполняется в A–AN, строки 2–1001; ПО — A–AI, строки 2–1002. Более крупный набор делится на файлы по 1000/1001 строк, каждый с отдельным номером; ошибка любой части откатывает регистрацию всего запроса.

### Номера, неизменность и хранение

Миграция № 15 добавляет `frdo_packages` и `frdo_package_documents`. Журнал хранит UUID пакета, отпечаток запроса и номер части, категорию, исторические ОГРН/КПП, год выдачи, номер, время UTC, ID/версию/SHA-256 шаблона, относительный путь, SHA-256 результата и число строк. Состав содержит только ID выпускных документов, порядковые позиции и отпечатки источников; значения строк и отдельная база персональных данных не копируются в SQLite. UPDATE, DELETE, REPLACE и дописывание состава уже заполненного пакета запрещены триггерами.

Последовательность общая для ДПО и ПО в пределах ОГРН + КПП + года выдачи. Номер — следующий после максимального зарегистрированного; `BEGIN IMMEDIATE` и уникальный ключ исключают коллизии. Предпросмотр номера не занимает. Имя задаёт существующий `export_filename`: `ОГРН_КПП_ГГ_номер.xlsx`. Путь — `exports/frdo/<uuid>/<имя>.xlsx` в выбранном хранилище. UUID каталога предотвращает конфликт с файлом незавершённой попытки, номер которой не был зарегистрирован. Штатный перенос хранилища переносит весь каталог `exports` вместе с журналом.

Все файлы запроса создаются исключительно с новым именем, сбрасываются через fsync, считываются и сверяются до commit SQLite. На системах, поддерживающих fsync каталога, синхронизируются и каталоги. При обычном исключении транзакция откатывается, собственные незарегистрированные файлы убираются; уже зарегистрированные файлы никогда не удаляются обработчиком. При аварии процесса до commit возможны непривязанные файлы; они не становятся пакетами, не занимают номер и отображаются отдельным предупреждением. Их следует сохранить отдельно перед повторной подготовкой, а не загружать на портал как зарегистрированный результат. Автоматического удаления таких остатков нет.

Повторный запрос идентичного набора источников возвращает уже сохранённые пакеты, проверив SHA-256, без генерации и нового номера. Если любой выбранный документ ранее входил в другой запрос, новый пакет требует явного подтверждения с перечнем прежних номеров. Старый XLSX остаётся неизменным после уточнений. Номер не отражает передачу или принятие ФИС ФРДО.

### Повторное получение и восстановление

В нижнем журнале выберите пакет и «Получить файл пакета»: сохраняется побайтная копия с тем же SHA-256. Выберите новое имя назначения; существующие файлы не перезаписываются. Получение не зависит от активной версии шаблона или текущей готовности карточек.

При каждом показе журнала и получении файла проверяются доступность и SHA-256. Отсутствие/повреждение показывается ошибкой конкретного пакета; приложение не скрывает её повторной генерацией. Для восстановления:

1. Найдите исходный XLSX в резервной копии хранилища либо ранее полученную неизменённую копию.
2. Если управляемый файл повреждён, сначала переместите его отдельно, сохранив для разбора; приложение его не заменяет.
3. Выберите пакет → «Восстановить из копии». Принимается только исходная контрольная сумма из журнала и корректная структура XLSX; восстановление возможно только на отсутствующий путь. Новый номер не создаётся.

Если идентичных байтов нет, восстановить прежний пакет регенерацией нельзя. Сохраните журнал с ошибкой; отдельная новая подготовка после явного подтверждения создаёт новый пакет. Резервировать нужно хранилище целиком, включая SQLite, templates и exports. Как и существующий локальный архив, XLSX содержит персональные данные и защищается правами доступа к выбранному локальному хранилищу; отдельное шифрование/учёт пользователей не добавлены. Произвольное внешнее удаление или повреждение обнаруживается при проверке файла, но не предотвращается SQLite.

### Границы P05.3

Фиксируется только подготовка XLSX. Прямой отправки, статусов «Передано»/«Принято», учёта отклонений, дубликатов и сложных исправлений нет. Совместимость подтверждается структурными проверками и локальными тестами предоставленных файлов; **фактический пробный импорт на портал ФИС ФРДО ещё не проведён, принятие реестром не заявляется**. Другие редакции официальных шаблонов требуют явной проверки профиля. Стабильный Release не публикуется.
