# Безопасность Proficentr Desktop

Официальный источник: https://github.com/AlekseyVinokurov/proficentr-desktop. Только подписанные пакеты из Releases этого репозитория предназначены для встроенного обновления. Артефакты Actions — проверочные сборки; наличие исходников или форка само по себе не подтверждает безопасность стороннего EXE.

Данные хранятся локально в выбранном организацией каталоге, отдельно от программы. Программа не отправляет базу, сведения слушателей и организаций, документы или вложения разработчику, в облако или сторонним организациям. Нет телеметрии, аналитики и удалённого доступа к базе.

Единственная сетевая функция приложения — проверка и получение официальных обновлений через GitHub API, GitHub Releases и официальный адрес перенаправления файлов `release-assets.githubusercontent.com`. GitHub получает IP-адрес и стандартные технические метаданные; пользовательские сведения в запросы не включаются. Системные прокси для этих запросов не используются. Обычная работа доступна без интернета. Новые сетевые функции требуют отдельного решения, документации и явного согласия на соответствующую операцию.

Установка требует подтверждения, подписи Ed25519 встроенным ключом, совпадения версии, совместимости, размера и SHA-256 ZIP. Ключ из загрузки не принимается. Helper переключает каталоги после выхода приложения, без повышения прав; прежние файлы сохраняются. Перед миграциями существующей SQLite создаются проверенные копии через Backup API с учётом WAL и проверяются миграции на копии. Автоматического восстановления старой базы нет: это могло бы уничтожить новые записи. Порядок восстановления и ограничения описаны в [docs/updates.md](docs/updates.md).

SQLite сама по себе не шифрует данные и не защищает их от копирования. Пароль Windows не заменяет комплексную защиту. Организация отвечает за управление доступом, резервное копирование, защиту носителей и необходимые организационные и технические меры в пределах своих законных обязанностей. Роли, аудит изменений и шифрование базы пока не реализованы; соответствие всем требованиям законодательства не заявляется.

## Сообщить об уязвимости

Если в разделе **Security → Advisories** официального репозитория доступна кнопка **Report a vulnerability**, используйте GitHub Private Vulnerability Reporting. Доступность зависит от настроек владельца. Если кнопки нет, можно открыть публичный Issue только с просьбой включить приватный канал, без технических деталей эксплуатации и чувствительных данных.

Никогда не прикладывайте в публичные Issues рабочие базы, ФИО, СНИЛС, паспорта, документы, ключи или токены. Для воспроизведения используйте вымышленные сведения. Не отправляйте реальные данные даже в приватном сообщении без отдельной необходимости и согласования безопасного способа передачи.

CI использует pytest с запретом реальной сети, Bandit, целевую политику сетевых импортов/адресов/ключа, Gitleaks и pip-audit. Это дополнительные проверки, а не доказательство отсутствия уязвимостей. Проверка ключа в политике требует защиты исходников и проверки изменений; локальный злоумышленник с правами записи в EXE или данные находится вне доверенной границы обновления.
